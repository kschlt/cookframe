# bring-compat — CFV1-S3 Bring compatibility spike (Gate D)

Observation run against Bring, using disposable public pages as the recipe source. Evidence for
the capability-URL design (OQ-17), the Slice 3 Schema.org mapping, and the hosting decision
(OQ-05). This spike produces **evidence, not decisions** — it closes no open question.

This is the one backlog item that deliberately precedes the toolchain, so its proofs are
**artifacts a reader checks**, not evals a harness runs. Fixtures are shaped so the Slice 0 eval
harness can pick them up later without rework.

## What's here

- `findings.md` — one verdict-bearing section per enumerated question. Read this first.
- `public-url-requirement.md` — the OQ-05 premise stated as an explicit yes/no with its evidence,
  in a form the hosting record can cite.
- `protocol.md` — the on-device observation kit (the half that lives in the Bring app, not its
  HTTP traffic): import each page on a phone and record what you see. One section per question.
- `pages/` — the disposable source pages (synthetic recipes; no real recipe, no personal data,
  no real photo). Generated by `make_pages.py`.
- `fixtures/*.json` — Bring's parser output pinned per question, so a later Bring change fails
  loudly. Regenerated by `record.py`.
- `make_pages.py`, `record.py` — regenerate the pages and re-record the observations.

## How Bring import works (observed)

Bring imports a recipe by opening a deep link whose payload calls
`https://api.getbring.com/rest/bringrecipes/parser?url=<recipe url>`. That endpoint fetches the
recipe URL **server-side from Bring's infrastructure** and returns Bring's parse as JSON — the
structure the app then renders. The fixtures pin that JSON.

## Reproduce

```
python3 spikes/bring-compat/make_pages.py            # regenerate pages
git commit && git push                               # publish them (raw.githubusercontent serves them)
python3 spikes/bring-compat/record.py --sha <commit> # re-record parser output at that commit
```

`record.py` pins page URLs at a fixed commit (`pages_pinned_at` in each fixture) so an
observation is reproducible. The device half (`protocol.md`) is run by hand on a phone.
