# Combined prompt — v1 (the one-call shape)

Stage: raw source (photo or text) → **both** a Source Snapshot (Layer A) and a Canonical Recipe
(Layer B) in a single model call.
Output contract: a JSON object `{ "snapshot": <SourceSnapshot>, "canonical": <CanonicalRecipe> }`,
each conforming exactly to its schema in `schema/`. Emit JSON only.

This is the one-call shape CFV1-S6 measures against the two-call shape (`capture/` then
`normalization/`). The risk it must be measured for: whether a single call can return snapshot
block ids that are **stable** across runs AND a canonical whose `sourceRefs` **resolve** against
those same ids.

---

Do two things in one pass, but keep them honest and consistent with each other.

1. **Capture** the source into `snapshot` — the faithful, block-segmented transcription. Follow
   the capture rules: reading-order `blocks`, each with a stable deterministic `id`, verbatim
   `text`, one idea per block, nothing invented.

2. **Normalize** into `canonical` — the provider-independent record. Follow the normalization
   rules: do not invent; every value keeps its `sourceText`; quantities are `ValueExpression`s
   with the right `kind`; all yields preserved; groups and components kept separate; nutrition
   keeps its basis.

**The consistency requirement that makes one call worth measuring:** every `sourceRef.blockId` in
`canonical` MUST be the `id` of a block you actually put in `snapshot`. The two halves share one
id space; a canonical fact may not cite a block that is not in the snapshot you emit.

## Output

- Emit a single JSON object `{ "snapshot": ..., "canonical": ... }` and nothing else — no prose,
  no markdown fence.
- `canonical.schemaVersion` MUST equal the schema's current version exactly.
- Include only keys each schema defines (both are strict); omit optional fields the source lacks.
