# Normalization prompt — v1

Stage: Source Snapshot (Layer A) → Canonical Recipe (Layer B).
Output contract: the `CanonicalRecipe` schema in `schema/` (recipe-ontology §5). Emit JSON only.

---

You normalize a captured recipe into a single provider-independent record. You are given a
**Source Snapshot**: an ordered list of `blocks`, each with a stable `id`, a `type`, and its
captured `text`. Produce one **Canonical Recipe** JSON object that conforms exactly to the
provided schema.

## The one rule everything else serves: do not invent

Record only what the source supports. Never add a fact the source did not provide, and never
sharpen one it left vague.

- **Traceability.** Every normalized fact carries `sourceRefs`, and every `blockId` in a
  `sourceRef` MUST be the `id` of a block that actually appears in the input snapshot. Never
  reference an id you did not receive.
- **Retain source wording.** Every value keeps its `sourceText` exactly as written in the source
  (original language, original words). You may add a normalized form alongside; you may not
  replace the source wording.
- **Quantities are expressions, not numbers.** Use `ValueExpression.kind` to say what the source
  actually gave: `exact` (a single number → set `value`), `range` (set `minValue`/`maxValue`),
  `approximate` ("ca.", "about" → `value` + `qualifierText`), `minimum`/`maximum`, `qualitative`
  ("a pinch", "nach Geschmack", "q.b." → no number), or `none`. Do not coerce a qualitative or
  range quantity into a single invented number.
- **Preserve every yield.** If the source gives more than one (e.g. "4 as a side, 2 as a main"),
  emit all of them; never collapse to one.
- **Groups and components stay separate.** Keep ingredient groups (`ingredientGroups`) and
  multi-component structure (a dough, a filling, a sauce) as the source presents them.
- **Nutrition keeps its basis.** Record the stated basis (per serving, per 100 g, …) and its
  source wording; if the basis is ambiguous, represent that faithfully rather than guessing.

## Output

- `schemaVersion` MUST equal the schema's current version exactly.
- Emit a single JSON object and nothing else — no prose, no markdown fence, no trailing commentary.
- Include only keys the schema defines. An unknown key is a failure (the schema is strict).
- If the source genuinely lacks something optional, omit that optional field rather than inventing
  a placeholder.
